## 1. Executive overview

This release ships the **Plan module**: one page (`/mes-app/plan`) that carries a production job through
the full floor lifecycle — **Unscheduled → Acknowledged → Vacuum/Press → Panels Ready → Assembly →
Merge → Merged-with-chassis → QC** — per the ratified business-rules document (2 Jul). The old
**"Planning" menu (Board + Cockpit) is retired**; `/planning*` URLs redirect to `/plan`. Around the
module, the release carries a set of Michael-directed costings/chassis UX restorations and two defect
fixes found during live testing.

**Operating context (BA note):** this work was executed under the Rapid-Prototype directive
(Michael, 2 Jul — mockup as source of truth, speed over ceremony, direct owner sign-off per feature).
This document is the ceremony catch-up: everything below is in ONE squash commit, CI-green, tagged.

## 3. Business rules implemented (for BA ratification)
1. **Production-job lifecycle** (Michael's authoritative doc, 2 Jul): all states reversible until
   MERGED WITH CHASSIS; planner backward-moves on merged jobs rejected with a toast; drawer/inspector
   revert affordances hidden for merged jobs.
2. **Single-location rule** (Michael, 2 Jul): the job card exists in exactly one zone; the V/P→Panels-Ready
   transition is the planner's explicit drag (`declareCut()` is the single swap point for the future
   Panels-Cut-Complete shop-floor event).
3. **BOM display rule** (Michael, 3 Jul): job BOMs on /plan show the live costing sheet without
   ratios/margins/discounts; monetary columns gated on `bom.view_full_cost`.
4. **Menu consolidation** (Michael, 3 Jul): /plan is the planning surface; Planning menu retired.

**Open BA decision:** the new "Plan" nav entry is currently **ungated** (visible to every authenticated
user — rapid-prototype demo choice). Recommend gating on `planning.view` at Phase-2 hardening.

## 4. Data & schema
- **0032** `icb_mes.plan_floor_state` — single-row JSON document (one factory). Additive; inspector-guarded; empty on first boot → /plan starts with a blank floor in prod. Not event-sourced (deliberate: event-level floor integration is the next phase).
- **0033** `chassis_records.type_image` + `chassis_models.image_file` — nullable varchar columns. Additive; inspector-guarded.
- New static assets: `backend/app/static/chassis-types/*.png` (10 files, ~10 MB), `backend/app/static/plan/*` (mockup art, committed earlier in the arc).
- **No destructive operations, no data backfills, no changes to existing columns.**

## 8. Prod deploy runbook (week of 6 Jul)
Target: ICB intranet VM — nginx :443 → uvicorn :8000 (internal), PostgreSQL 16, app at
`https://192.168.0.251/mes-app/`, autologin OFF, real logins.

```bash
# 0. Preconditions: backend/.env has DATABASE_URL (postgresql+psycopg://…) + SESSION_SECRET.
#    Optional but recommended for Pre-Job emails: SMTP_URL + EMAIL_FROM (empty = emails silently off).
# 1. Snapshot first (rollback anchor):
pg_dump "$DATABASE_URL" -Fc -f /backup/icb-pre-v1.40.0.dump
# 2. Fetch the exact release:
git fetch origin --tags
git checkout v1.40.0            # detached at the squash commit of backport/v1.39-base
# 3. Backend deps (into the venv the service runs from — NOT global python):
backend/.venv/bin/pip install -r backend/requirements.txt   # no new deps in this release; safe no-op
# 4. Migrations (additive; inspector-guarded; safe to re-run):
cd backend && ../backend/.venv/bin/alembic upgrade head && cd ..
#    expect: 0031 -> 0032 -> 0033
# 5. Frontend build ON the server (dist is gitignored, never committed):
npm --prefix frontend ci && npm --prefix frontend run build
# 6. Restart the app service (uvicorn app.main:app --host 0.0.0.0 --port 8000 from backend/.venv).
# 7. Smoke: GET /health; login; header shows v1.40.0; /mes-app/plan renders (blank floor);
#    /mes-app/costings View opens in-shell; /mes-app/admin/chassis-models lists 10 types.
```
**Parity guarantee:** what Michael tested on :8000 IS this artifact — after the squash-merge his
:8000 checkout was switched to `backport/v1.39-base` at the merge commit and rebuilt (same commit the
tag points at; same build steps as prod).

**Rollback:** `git checkout v1.39.7 && npm --prefix frontend run build` + service restart. The two new
migrations are additive — leaving the tables/columns in place under v1.39.7 is harmless (no code
references them); a full down-migrate (`alembic downgrade 0031`) is available but not required.
